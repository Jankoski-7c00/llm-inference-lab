## 八、统一实验记录模板(所有方向共用)

每个实验 / 项目按此模板记录:

1. **问题与场景**:模型、dtype、batch/token 数、context length、并发、硬件
2. **基线与瓶颈假设**:Kernel latency、HBM 带宽、compute 利用率、transfer/sync
3. **方案与取舍**:为什么改 Runtime / Compiler / layout / Kernel
4. **结果**:同时记录微基准和 TTFT、TPOT、throughput、峰值显存
5. **适用边界与失败尝试**:优化在哪些 shape 或场景中无效
6. **可迁移结论**:把具体实现抽象成通用方法

## 九、红线纪律

1. 每季度只有一个核心问题、一个主项目 —— 不开新坑。
2. 所有性能优化必须建立端到端闭环,Kernel latency 只是中间指标。
3. 涉及实际工作场景的代码和数据时,只保留脱敏的方法、指标定义和架构理解。
4. 学习以可验证交付物为单位:代码、benchmark、设计文档、技术分享、复盘,至少占两样。
