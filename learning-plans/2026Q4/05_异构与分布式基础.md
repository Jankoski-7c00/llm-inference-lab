## 1. 方向定位与季度目标

### 为什么本季度只打底

- 职业规划原则：每阶段只推进两项主线能力，控制并行主题数。2026 Q4 的主线
  在别的方向（编译器与单卡/单 NPU 性能），本方向是**第三优先级、提前打底**。
- 异构 Runtime 与分布式推理是 2027 年起第二阶段的主战场。现在投入 10% 时间
  建立词汇表和问题意识，是为了让 2027 年系统学习时"每个概念都见过面"，
  降低那时的认知坡度，而不是现在就把这些内容学透。
- 每周 1 小时不足以做任何有深度的系统项目，强行展开只会两头落空。因此
  本季度的最高纲领是：**建立词汇表、建立问题意识、结合实践完成一次观察**。

### 与第二年（2027）计划的衔接

- 长期学习范围（完整版，2027 年逐步展开）：
  - 异构侧：device placement、graph partition、cost model、stream、event、
    command queue、异步执行、memory pool、DMA、dependency 与 pipeline scheduling
  - 分布式侧：TP / DP / PP / EP、AllReduce / AllGather / ReduceScatter /
    AllToAll、MoE EP、Prefill/Decode 分离、KV 传输与通信计算重叠
- 本季度只碰前半部分的**入口概念**：stream / event / 异步执行 / memory pool
  的基本语义；TP / PP / EP 的区别；一次实践中的 GPU↔NPU 数据路径观察。
- 2027 年接手时的理想起点：读 vLLM / Megatron-LM 相关文档不需要先查名词；
  讨论异构调度时能正确使用 stream、event、bubble、overlap ratio 这些词。

### 12 月底应达到的状态（Definition of Done）

1. 能不查资料说出 stream / event / command queue / memory pool 各自解决什么问题。
2. 能用一句话分别说明 TP / DP / PP / EP 切分的对象是什么。
3. 能说出 AllReduce 与 ReduceScatter + AllGather 的关系。

5. 产出一份本方向的个人词汇表 + 概念笔记（见第 6 章交付物清单）。

## 3. 月度路线图

### 10 月：异构执行概念 —— stream / event / command queue / memory pool

目标：把"异步执行"这件事的概念骨架立起来，能映射回实际异构加速器平台的对应物。

- W1（10/1–10/11，国庆假期弹性）：CUDA 文档 Asynchronous Concurrent
  Execution 章节通读，重点：stream 语义、default stream 的隐式同步陷阱。
- W2：event 与计时——`cudaEventRecord` / `cudaEventElapsedTime` /
  `cudaStreamWaitEvent`；跨 stream 依赖如何表达。
- W3：memory pool 与异步分配——为什么频繁 `cudaMalloc` 会隐式同步、
  caching allocator / stream-ordered allocator 的动机（类比实践中 NPU 侧
  的内存管理机制）。
- W4：月度收束——写一页"概念对照表"：CUDA 概念 ↔ 实际异构平台中的对应
  机制（command queue / DMA 队列等，按平台通用术语填写），
  只写概念层，不涉及任何非公开细节。

月度出口标准：能回答"为什么 transfer 和 compute 可以 overlap？需要哪些条件？"

### 11 月：分布式并行词汇表 —— TP/DP/PP/EP + collective 通信

目标：建立并行策略与通信原语的词汇表，达到"开会能听懂、能提问"的水平。

- W1：四种并行策略切分对象——TP（层内权重矩阵）、DP（数据/请求）、
  PP（层/stage）、EP（MoE 专家）；各自解决什么瓶颈（显存 / 吞吐 / 延迟）。
- W2：Megatron-LM 论文（1909.08053）通读，重点看 column/row parallel
  linear 的切法与通信发生的位置；不推公式，只建立直觉。
- W3：collective 原语——AllReduce / AllGather / ReduceScatter / AllToAll
  的语义、数据量公式；ring AllReduce 的带宽直觉（读 NCCL 文档对应章节）。
- W4：月度收束——画一张"并行策略 × collective"对照矩阵：每种并行在
  forward / decode 的哪个位置触发哪种 collective，量级多大。

月度出口标准：能回答自测题（见第 6 章）中并行与通信部分的全部问题。

### 12 月：结合实践画一张 GPU↔NPU 数据路径时间线草图（脱敏）

目标：把前两个月的概念用到一个真实观察上，形成可复用的方法论模板。

- W1：选路径——挑实践中一条熟悉的 GPU→NPU（或反向）数据路径；
  列出参与方：谁发起、经过哪些队列/DMA、终点是谁。
- W2：估字节量——对每一段 transfer 估算字节量与理论时间
  （bytes ÷ 有效带宽），标出实测口径（如 profiler / 日志时间戳，按可获得的
  方式获取）。
- W3：画时间线草图——按第 5 章的要素清单画出 compute / transfer /
  sync 三段的时间关系，标出 bubble 位置与大致占比。
- W4：季度复盘——对照第 6 章验收标准自测；整理词汇表定稿；
  写一段"2027 年开工时的 5 个问题"，作为第二阶段入口。

月度出口标准：交付 1 张脱敏时间线草图 + 季度复盘笔记。

> 脱敏原则：图中不出现真实芯片型号、真实带宽数字、真实模型/算子名；
> 只保留相对比例、量级（如"数十 MB 级"）和方法论结构。对外分享前
> 再过一遍检查。

## 5. 实验与观察方法

原则：**轻量为主**。本季度实验最多 2–3 次，单次含环境准备不超过 1 小时；
任何需要"搭环境超过 30 分钟"的实验直接砍掉，降级为阅读 + 画图。

### 实验 A（可选，11 月）：PyTorch collective 观察

- 有条件（两卡机器）：用 `torchrun` + `torch.distributed`（NCCL 后端）跑
  AllReduce / AllGather / ReduceScatter 各一次，扫几档 message size，
  记录耗时，算有效带宽（bytes / time），与理论互联带宽对比。
- 只有单卡：用 Gloo 后端在本机跑通 collective 语义（正确性而非性能），
  重点理解每个 collective 的输入输出 shape 变化。
- 无条件（无可用 GPU 环境）：完全跳过实验 A，改为精读 NCCL 文档中
  collective 语义章节 + 手绘各 collective 的数据流图。

### 实验 B（12 月，核心）：GPU→NPU 数据路径观察与画图

- 数据获取：优先用现有的 profiler / 日志时间戳；若拿不到精确数字，
  用"理论时间 = 字节量 ÷ 标称带宽 × 经验折扣"估算，并在图上标注"估算"。
- 产出：一张时间线草图（手绘或 PPT/Excalidraw 均可），脱敏后归档。

### "时间线草图"应包含的要素（检查清单）

1. **参与方**：Host / GPU / NPU / DMA（或平台对应的传输引擎）各一条泳道。
2. **发起方**：每一段 transfer 由谁发起（runtime? driver? 显式 API?）。
3. **字节量**：每段 transfer 的字节量与量级标注（脱敏：只保留量级与相对比例）。
4. **同步点**：event / fence / queue sync 出现在哪里；哪些是隐式同步。
5. **依赖关系**：哪段 compute 等哪段 transfer，用箭头标明 dependency。
6. **bubble**：设备空闲段标红，注明原因（等数据 / 等同步 / 排队）。
7. **overlap ratio**：transfer 与 compute 重叠的时间占比（粗略即可）。
8. **一句话结论**：这条路径当前瓶颈在 compute、transfer 还是 sync。

### 贯穿全年的性能指标意识（遇到就记进词汇表）

- GPU/NPU 利用率（utilization）
- transfer bytes / transfer time 与有效带宽
- sync time（host 阻塞等 device 的时间）
- overlap ratio（重叠时间 / 总时间）
- bubble（pipeline 或设备空闲段）

## 6. 能力验收标准

### 自测问题清单（12 月底闭卷自答）

异构执行概念：

1. stream 和 event 分别解决什么问题？default stream 的隐式同步陷阱是什么？
2. `cudaStreamWaitEvent` 与 `cudaStreamSynchronize` 的语义差别？
3. 为什么异步 memcpy 要求 host 侧 pinned memory？
4. memory pool / caching allocator 解决了什么性能问题？为什么频繁分配会引入同步？
5. command queue 模型下，host 与 device 的执行关系是怎样的？

并行策略与通信：

6. TP 和 PP 切分的对象分别是什么？各自引入的通信发生在什么位置？
7. DP 与 TP 在推理场景下分别扩的是什么（吞吐 vs 延迟）？
8. EP 切分的是什么？为什么 MoE 的 EP 通常伴随 AllToAll？
9. AllReduce 与 ReduceScatter + AllGather 的关系是什么？
10. 一个 hidden size 为 H、batch × seq 为 S 的激活，TP=N 时一次 AllReduce
    大约搬多少字节？

瓶颈判断：

11. 什么情况下 transfer 会成为瓶颈？（提示：字节量 vs 带宽 vs 能否 overlap）
12. pipeline bubble 由什么决定？micro-batch 数量如何影响它？
13. 通信计算重叠（overlap）成立需要哪些条件？

评分：13 题中答对 ≥ 10 题视为达标；答错的题目记入 2027 年 Q1 的第一个

## 7. 风险与降级方案

### 本方向的优先级定位

本方向是 2026 Q4 **优先级最低**的方向（占比 10%）。当季度时间被压缩时，
它是**第一个被暂停**的对象；暂停本方向不视为计划失败。

### 暂停规则（自上而下依次执行）

1. **软降级**：某两周没时间 → 砍掉当周轻量实验，只保留 20 分钟阅读 +
  10 分钟笔记；月度出口标准不变。
2. **硬暂停**：主线方向（编译器/性能）冲刺期 → 本方向整体暂停，暂停期间
  只允许"顺手记"（实践中碰到相关概念时花 2 分钟记进词汇表）。
3. **放弃 12 月实验 B**：若到 12 月中旬仍未启动时间线草图，则降级为
  "阅读一篇别人的 timeline 分析 + 画虚构示例图"，方法论保留，实践观察
  顺延至 2027 Q1。

### 暂停后的快速恢复协议

- 恢复入口永远是**词汇表**：重读自己写的词汇表（约 10 分钟）即可回到语境。
- 恢复后的第一周不补错过的内容，直接从当前月份路线图的当周位置继续。
- 若暂停跨越整个月：跳过该月，但保留该月的"月度出口标准"作为 2027 年
  的 backlog 条目。
- 每季度末无论暂停与否，都执行 12 月 W4 的复盘动作（30 分钟版），
  保证与 2027 年计划的衔接不断链。

### 范围蔓延防护

- 出现"想搭个多卡环境试试看"的冲动 → 先写进 2027 backlog，本季度不动手。
- 出现"顺便把 TVM runtime 的 stream 实现读了"的冲动 → 同上，记入 backlog。
- 判断标准：任何单点投入预估超过 2 小时的动作，默认属于 2027 年范围。
